# 授信报告生成器（公开演示副本）

面向 A 股上市公司授信研究的本地 Streamlit 演示项目。它把可回查的来源材料和经过资格核对的
财务事实送入写作、逐句核对和独立审阅流程，并展示报告草稿及其问题。

**这是面试演示，不是生产授信审批系统；草稿不能代替人工判断。**

> **关于本副本。** 这是一个**代码副本**，从内部工作仓库复制而来，用于公开和本地复现。
> 内部的历史运行结果、上传的真实材料、数据库、日志和一次性探针产物**都没有包含在内**。
> 本副本附带**本案例的六份输入文件**（三份电子 PDF ＋ 三份财务 XLSX），它们**不**随内部仓库
> 分发，是本批次为本副本单独附上的；来源与权利状态见第六节。三份 PDF 已核实与法定披露平台
> 提供的下载件**逐字节相同**，三份 XLSX 是**人工整理**的工作簿、并做过元数据清理。
> **没有任何一份被核实为获得再分发许可**，版权与数据权利归原权利人所有。
> 本副本**不对应内部仓库的任何一次提交**（见第九节「代码状态」）。

## 一、已验证环境与安装

本次交付实测环境：**Windows 11 Home China / CPython 3.12.7 / 全新隔离虚拟环境**。
按锁定清单安装后解析到的关键版本：`streamlit 1.65.0`、`pandas 3.0.6`、`torch 2.14.1+cpu`。

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt
```

- **本文档记录的所有读数都是用这条命令装出来的环境测的**（165 个包）。锁定清单里
  `pypdf` 钉在 `6.19.0`；下面第三节的 block 数、第四节的套件读数都以这个版本为准。
- 安装约 **1.9 GB**（含 `torch`）。这些是 `retrieval/embedding.py` 的懒加载依赖：
  实测演示页面跑起来时 `torch` / `chromadb` / `sentence_transformers` / `transformers`
  **一个都没有被 import**。但依赖清单保留完整声明，以便真实运行和研究侧检索可用。
- [requirements.lock.txt](./requirements.lock.txt) 是一份**解析快照**，不是最低版本要求。
  若你想按不带钉版本的 [requirements.txt](./requirements.txt) 安装，请注意它只写
  `pypdf>=5.0.0`，不同版本会改变三份 PDF 的解析 block 数（见第二节警示）。
- 两个清单都是 **ASCII-only** 的：pip 按控制台区域编码解码依赖清单，
  在 GBK/cp936 的 Windows 控制台上，含中文注释的清单会在安装前直接 `UnicodeDecodeError`。

## 二、从空副本准备输入权威（必须先做一次）

`data/evidence.db` 与 `data/financial_v2.db` 是**运行期产物**，不随副本分发——它们必须由本副本
携带的六份输入在**你的机器上重建**。重建用一条命令完成：

```bash
# 只校验六份文件的 SHA-256 并打印将要执行的步骤，不写任何文件
.venv/Scripts/python.exe -m scripts.prepare_case_inputs --check

# 校验通过后真的执行：登记三份 PDF 建 evidence 库 + 由三份 XLSX 建财务快照
.venv/Scripts/python.exe -m scripts.prepare_case_inputs
```

身份参数（每份 PDF 的 `document_id` / `source_type` / `material_group`、财务的工作簿顺序 /
`scope` / `currency` / 声明公司名）写在 [data/samples/300750/case_inputs.yaml](./data/samples/300750/case_inputs.yaml)，
本副本专有；该文件同时声明了**期望产出**，供你核对。实测本次重建得到：

| 产出 | 值 |
|---|---|
| `evidence_set_version` | `set-501395a7ad5a` |
| 三份 PDF 的 block 数 | `288 / 301 / 177`（**随 `pypdf` 版本变化**，见下方警示） |
| 财务 `snapshot_id` | `snap-5c912da539bc643fe3fad7e54735553e`（112 项指标 / 432 条读数 / 期末 `2026-03-31`） |

> **警示：`evidence_set_version` 不覆盖 PDF 解析库版本。** 同一批 PDF 字节、同一份解析
> 代码，只因 `pypdf` 版本不同，三份 PDF 被切成 **288 / 301 / 177**（`pypdf 6.19.0`）
> 或 **292 / 300 / 177**（`pypdf 6.11.0`）个 block。`requirements.txt` 只写 `pypdf>=5.0.0`，
> 所以**每次全新安装解析到的版本可能不同**，block 数也会跟着变；`evidence_set_version`
> 在这一变化下**不变**。因此上表第二行是「本机实测」，不是可跨环境断言的不变量。
> 要复现本文记录的读数，请按 [requirements.lock.txt](./requirements.lock.txt) 钉版本
> （该文件里是 `pypdf==6.19.0`）。
>
> **据此，本副本不承诺「跨 `pypdf` 版本得到相同的解析产物」。** block 切分、以及任何按
> block 计数的读数（例如三份文档的 block 数）都可能随版本不同而变化；而
> `evidence_set_version` 因为不含库版本，**不会**跟着变——也就是说，同一个
> `evidence_set_version` 底下可能对应两套不同的 block 切分。不要拿 `evidence_set_version`
> 相等去推断「解析结果逐条相同」，也不要拿 block 数去跨环境比对。
> 财务 `snapshot_id` 只由三份 XLSX 的**字节**派生，与 `pypdf` 版本无关。

要点：

- 真正执行（不加 `--check`）时，目标库已存在就**默认拒绝**（这两个库是运行期权威，静默重建会让
  「本次基于哪份输入」不可追溯）。要重建请先移走旧库。`--check` 不写盘，因此库在不在都能跑。
- 它**不联网、不调用大模型、不读任何历史数据库**，只调用两个既有入口
  （`python -m evidence.builder`、`python -m scripts.prepare_financial_snapshot`）。
- 生成的两个 `.db` 是运行期产物，已被 `.gitignore` 排除，**不属于**拟公开内容。

这一节只说明**流程接线能跑通**。它**不**证明正文质量、选材质量或真实 Writer 的表现。

### 5. 不联网的确切含义

- `offline` 模式会装上一个**只覆盖大模型调用入口**（`LLMClient.chat_with_usage` / `chat` /
  `get_client`）的网络守卫；它**不**拦截裸 HTTP，也不阻断其他库自己发起的请求。
- **没有做过断网实测**（没有真的拔网线／断网卡跑一遍）。做过的只是**采样观测**：上批在
  一次等价的 `offline` 运行窗口内按 20 秒间隔读本机 TCP 表，共 **58** 个采样点覆盖
  `09:15:41Z → 09:34:53Z`，属于 Python 进程的非环回套接字里**已连接数为 0**；唯一反复出现的
  是一个 Python 进程 `LISTENING` 在 `0.0.0.0:8765`（本机另一个常驻服务，不是本演示链，
  也不是本链发起的连接）。**本批这次新运行没有重复做 TCP 采样**；它自己的网络记录只有
  `chain.log`，其中**没有**任何联网行（全文见交付报告）。
- 上面那段采样与本次的 `chain.log` 加起来仍只是一段窗口、一类观测，**不能**据此说「整条链
  不联网」。若你在意绝对无外联，请在容器或防火墙层阻断。

## 七、系统如何工作

```text
电子 PDF / Excel
  → 来源定位、Evidence 与研究 Pack；财务事实另走权威数据通道
  → Writer 依据当前材料和合格事实写自然正文，每句标注引用
  → 确定性逐句检查引用、期间及高风险数字等硬底线
  → 独立、只读的语义审阅指出遗漏、越界和矛盾
  → 带逐句问题的预览；系统放行与人工接受分别记账
```

当前写作主线是 **Pack 之后直接生成带引用的正文**，不是先批准原子 `ClaimCandidate` 再逐字拼句。
研究 Harness、Pack 来源、事实资格和财务权威各自保持边界；Writer 不能自行检索、计算或批准自己的事实。
历史 Claim 链保留供兼容和审计，不是当前演示的必经写作链。

主营业务的原表以已登记电子 PDF 的**原件区域**供人工回查。它不是结构化 `TableObject`、
Pack/Writer 材料或数字权威；图片可见不等于正文可引用其中金额和比率。正文使用的营收、成本、
毛利等数字仍须另做格级资格核对，跨期计算由 Python/Decimal 完成。财务指标表则由权威财务事实
确定性生成，不能用原 PDF 截图替代。

本副本支持可提取文本的电子 PDF，以及财务 PDF／Excel 输入；**不**把扫描件 OCR、图片、PPT
或 Word 当作首版输入。外部搜索有单独的来源获取、快照和资格要求；**打开只读演示页不需要**
外部搜索或模型密钥。
